# ADR-0003: Versioned state, validation и миграции

- Статус: Принято
- Дата: 2026-08-09

## Контекст

Текущий `load()` достраивает поля неявно. Backup не содержит версии схемы. Повреждённые ссылки могут пройти поверхностную validation, а затем быть удалены cleanup-функцией. Изменение data shape без формальной миграции угрожает совместимости существующих данных.

## Решение

Persisted state и backup получают metadata с `schemaVersion`. Данные проходят единый pipeline:

```text
parse → structural validation → migration → referential validation → normalized state
```

Каждая migration:

- принимает одну известную версию;
- возвращает следующую версию;
- идемпотентна на уровне общего pipeline;
- не удаляет неизвестные данные без явного правила;
- покрыта unit test;
- не перезаписывает источник при ошибке.

До destructive migration или replace import создаётся recovery copy. Legacy backup без версии определяется отдельным документированным правилом.

## Последствия

- Изменения data shape становятся проверяемыми и обратимыми.
- Импорт старых backup остаётся поддерживаемым.
- Потребуется описать фактическую legacy schema до первой миграции.
- Validation должна различать исправимую legacy-запись и недопустимый файл.

## Рассмотренные альтернативы

### Продолжать подставлять defaults в `load()`

Отклонено: невозможно доказать, какие преобразования уже применялись и безопасна ли повторная загрузка.

### Принимать только backup новой версии

Отклонено: нарушает обязательную совместимость пользовательских резервных копий.
