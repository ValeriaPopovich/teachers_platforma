# ADR-0001: Эволюционный рефакторинг на Vanilla JavaScript и ES Modules

- Статус: Принято
- Дата: 2026-08-09

## Контекст

Текущее приложение работает на GitHub Pages и реализовано на HTML, CSS и Vanilla JavaScript. Основная проблема — смешение ответственностей в одном файле, а не отсутствие frontend framework. Одновременная смена архитектуры, runtime и пользовательского поведения увеличит риск регрессий и потери данных.

## Решение

Сохранить HTML, CSS, Vanilla JavaScript, Supabase JS v2 и GitHub Pages. Код постепенно перевести на ES Modules.

Сначала механически вынести существующие scripts без изменения поведения. Переход на `type="module"` выполнить отдельным изменением после smoke-проверки, поскольку modules меняют порядок выполнения, область видимости и strict mode.

Bundler не добавлять, пока приложение, тесты и GitHub Pages работают без него.

## Последствия

- Риск функциональных регрессий ниже, чем при полном переписывании.
- Существующие DOM-сценарии можно переносить постепенно.
- Не появятся framework-specific abstractions и зависимости.
- Разработчик продолжает явно управлять DOM и состоянием.
- Если позднее возникнет доказанная потребность во framework, потребуется новый ADR.

## Рассмотренные альтернативы

### Немедленный переход на React/Vue/Svelte

Отклонён: не устраняет автоматически проблемы schema migration, cloud conflict, RLS и привязки локальных данных к пользователю.

### Сохранить один inline script

Отклонён: не позволяет изолировать и тестировать domain-логику.
