# ADR-0002: Локальные данные принадлежат единственному аккаунту устройства

- Статус: Принято
- Дата: 2026-08-09

## Контекст

По продуктовой модели один browser profile используется только одним аккаунтом Teachers Platform. Поддержка переключения нескольких аккаунтов на одном устройстве не требуется.

Приложение уже использует единый localStorage key `tutorCabinet_v1`. Переход на отдельные keys по `user.id`, экран выбора владельца и сложная миграция legacy state были бы несоразмерны реальному сценарию.

При этом cloud upload не должен полностью полагаться на неявное предположение. Дешёвый owner marker защищает от случайной неверной session или ручной подмены localStorage.

## Решение

Сохранить единый ключ `tutorCabinet_v1`. Рядом хранить отдельный marker, например:

```text
tutorCabinet_owner_user_id
```

Правила bootstrap:

1. Если cloud содержит данные, он является источником истины: cloud state записывается локально, marker получает текущий `user.id`.
2. Если cloud пуст и marker отсутствует, существующий legacy state автоматически считается данными текущего — и единственного — аккаунта устройства.
3. После первого успешного cloud save marker получает текущий `user.id`.
4. Если marker не совпадает с текущим `user.id`, cloud upload запрещается и пользователь видит ошибку. Автоматический перенос или merge не выполняется.
5. При logout ожидающий save завершается или отменяется, runtime session очищается, локальная копия остаётся для того же аккаунта.

Application state может быть прочитан до завершения auth bootstrap, пока auth gate скрывает кабинет. Отправлять его в cloud до проверки marker запрещено.

## Последствия

- Не требуется менять существующий storage key и мигрировать нормальный пользовательский сценарий.
- Нет UI подтверждения владельца, списка локальных аккаунтов и нескольких caches.
- Первый legacy bootstrap остаётся автоматическим.
- Неожиданное несовпадение владельца безопасно останавливает sync вместо попытки угадать правильное действие.
- Сценарий нескольких аккаунтов на одном browser profile официально не поддерживается.

## Рассмотренные альтернативы

### Отдельный localStorage key для каждого `user.id`

Отклонено: продукт не поддерживает несколько аккаунтов на одном устройстве, поэтому дополнительная схема хранения и migration flow не окупаются.

### Не хранить owner marker

Отклонено: одна небольшая проверка предотвращает отправку локального state при неожиданной неверной session практически без архитектурной сложности.

### Очищать local data при logout

Отклонено: при неуспешном cloud save это может удалить единственную актуальную offline-копию.
