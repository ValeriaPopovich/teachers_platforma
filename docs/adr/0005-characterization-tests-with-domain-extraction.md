# ADR-0005: Domain extraction только вместе с characterization tests

- Статус: Принято
- Дата: 2026-08-09

## Контекст

Финансы, расписание и backup merge содержат критичные бизнес-правила, но не имеют автоматических тестов. Перенос сначала и тестирование позднее может закрепить незамеченную регрессию как новое ожидаемое поведение.

## Решение

Каждая критичная ответственность переносится отдельно и в том же PR получает тесты существующего поведения.

Порядок для каждого модуля:

1. Зафиксировать реальные входные данные и ожидаемый результат.
2. Добавить characterization/golden test.
3. Извлечь чистую функцию без намеренного изменения результата.
4. Сравнить результат с baseline fixture.
5. Только отдельным изменением исправлять обнаруженные бизнес-ошибки.

Первый приоритет: finances, затем schedule/lessons, затем backup validation/merge.

## Последствия

- Рефакторинг не зависит только от ручного smoke.
- Изменение финансового правила становится явно заметным в diff теста.
- Часть baseline сначала придётся зафиксировать вручную, пока функции находятся внутри IIFE.
- Тесты являются частью DoD каждого domain PR, а не отдельной поздней фазой.

## Рассмотренные альтернативы

### Сначала полностью разделить код, затем написать тесты

Отклонено: нет надёжного способа отличить сохранённое поведение от регрессии.

### Покрыть всё только E2E

Отклонено: финансовые и календарные edge cases быстрее и точнее проверяются чистыми unit tests.
