- Главное действие ровно одно на каждом виде («Войти» / «Отправить ссылку для сброса»), видно без прокрутки — OK.
- Состояния (D) в целом спроектированы в `auth.js`, а не «потом»: неверный формат почты, пустой пароль, неверные креды, неподтверждённая почта, rate limit, protivший session (`reauth`), несуществующий аккаунт при восстановлении, cooldown повторной отправки, короткий/несовпадающий пароль, заблокированный/истёкший доступ — все с текстом и próximo действием. - Пробел: нет отдельного состояния «нет сети» на сабмите (общий фолбэк «Не удалось выполнить действие: …») — не блокер, т.к. текст всё равно объясняет проблему.

### Ответы на 10 вопросов §10
1. Можно ли удалить хотя бы один внешний контейнер без потери структуры? — нет, gate/card/view-обёртки все функциональны.
2. Есть ли карточка «просто чтобы данные положить»? — нет, карточка — сама форма.
3. Почему у элемента именно такая форма/цвет/размер? — не объяснимо функцией: 28px-радиус, градиент фона и кнопки, тень 90px — чисто декоративные, без продуктовой причины (см. AUTH-02, 04, 07).
4. Дублирует ли цвет уже написанный текстовый статус? — нет, `.auth-message` всегда идёт с текстом.
5. Больше одного очевидного главного действия? — нет, ровно одно на вид.
6. Работает ли композиция при пустых/длинных данных? — да, длинный email экранируется (`escHtml`) и переносится в сообщении.
7. Можно ли увидеть больше полезной информации без ухудшения читаемости? — не требуется, это входная точка, а не рабочий экран.
8. Есть ли решение, явно связанное с работой преподавателя, а не с модным UI-паттерном? — тексты ошибок и cooldown — да, продуктовые; градиенты/pill/тень — нет, чисто визуальный тренд.
9. Не копирует ли экран референс вместо развития своей системы? — похоже на типовой AI-generated SaaS-логин (градиентный фон + градиентная кнопка + pill-лейбл + мягкая тень), тогда как остальной продукт — плоские панели без градиентов.
10. Соберёт ли разработчик экран только из утверждённых токенов и `Ui*`-компонентов? — нет: сырой HTML/легаси CSS вне Ui-kit, радиусы и тень не по шкале.

Вердикт: **вернуть на упрощение** — вопрос 3 и 9 триггерят возврат («назначение решения нельзя объяснить»). AUTH-01–03 обязательны перед приёмкой; AUTH-04–08 можно закрывать по мере миграции экрана на Ui-kit.

### Общий DoD прохода

- Unit: timeline до/во время/после и пересечения; minute boundary/visibility; ДЗ=5; neutral payment; package deduction; legacy parent fallback; auth page reset.
- E2E: новый аккаунт → ученик → занятие; повторный вход → dashboard; keyboard/reduced-motion условных полей; unclipped payments calendar; initial/filtered empty states.
- Visual QA: 1440, 1024, 768, 425 px; light/dark; normal/reduced motion.
- Quality gates: lint, stylelint, architecture guards, `npm test`, fresh compiled CSS, build и критические Playwright-сценарии.
