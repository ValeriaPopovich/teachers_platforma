# Включение серверного CAS для cloud sync

Клиент использует `src/cloud/sync-protocol.js` и `src/cloud/supabase-adapter.js`; обычного `upsert` для `app_data` больше нет. Серверная CAS-миграция применена в live Supabase 2026-08-09, поэтому облачная запись и защита от конфликтов между устройствами включены.

До применения миграции read-only REST-проверка возвращала `42703: column app_data.revision does not exist`. Этот исторический результат больше не описывает текущее состояние проекта.

## Применённая миграция

В live Supabase выполнен файл [`supabase/migrations/2026_stage5_add_revision_cas.sql`](../supabase/migrations/2026_stage5_add_revision_cas.sql).

Миграция:

- добавляет `revision integer not null default 1` и `schema_version integer not null default 1`;
- создаёт authenticated RPC `save_app_data(p_data, p_expected_revision, p_schema_version)`;
- обновляет строку только при совпадении expected revision;
- идемпотентна; rollback записан в комментарии файла.

Дополнительный diff или deploy клиентского кода не требуется.

## Проверка

1. Изменить данные: статус должен перейти `Сохраняем…` → `Сохранено`.
2. Перезагрузить страницу и проверить изменение.
3. Открыть две вкладки. Изменить первую, затем вторую: во второй остаётся сообщение «На другом устройстве есть более свежие изменения».
4. Проверить три действия: скачать копию с этого устройства, открыть данные с другого устройства или оставить данные с этого устройства. Последнее требует явного подтверждения и всё равно использует CAS.

Не возвращайте legacy `upsert`: CAS защищает более новую копию от молчаливой перезаписи.
