# Критический smoke-чеклист (ручной)

Повторяемый ручной прогон перед каждым выпуском. Автоматический browser-smoke (Playwright) — не сейчас (см. [REFACTORING_SPEC.md](./REFACTORING_SPEC.md) §4). Отмечать прохождение датой и версией.

| # | Сценарий | Ожидание | OK |
|---|---|---|---|
| 1 | Вход существующего пользователя и reload session | Кабинет открывается, данные на месте | ☐ |
| 2 | Создание и редактирование ученика | Сохраняется, отображается | ☐ |
| 3 | Создание регулярного и разового занятия | Появляются в расписании, дубли не создаются | ☐ |
| 4 | Завершение, отмена и перенос занятия | Статусы меняются, нет двойного начисления | ☐ |
| 5 | Разовая оплата и абонемент | Баланс/остаток пересчитываются | ☐ |
| 6 | Проверка баланса | Совпадает с ожиданием (долг/аванс/остаток) | ☐ |
| 7 | Backup export, replace import, merge import | Экспорт скачивается; replace заменяет; merge не ломает ссылки. После replace в localStorage появляется `tutorCabinet_recovery` | ☐ |
| 8 | Merge: платёж со ссылкой на занятие | После merge `payment.lessonId` указывает на новый (remapped) lesson, а не в никуда | ☐ |
| 9 | Cloud save и повторная загрузка | Статус «Сохранено»; после reload данные из облака | ☐ |
| 10 | Выбор версии данных (после применения миграции §5) | Изменение в двух вкладках/устройствах → понятное сообщение «На другом устройстве есть более свежие изменения», доступны скачивание копии с этого устройства и выбор данных; автоматической перезаписи нет | ☐ |
| 11 | Гейтинг доступа | Заблокированный (`status !== 'active'`) и истёкший (`access_until` в прошлом) аккаунт видит экран ограничения, не входит в кабинет | ☐ |
| 12 | Escape и Tab в модалках | Escape закрывает; Tab не уходит на фон; при закрытии фокус возвращается | ☐ |

После deploy вручную: вход, открытие ученика, сохранение занятия, оплата, reload, backup export.
